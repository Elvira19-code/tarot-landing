# Публикация на Timeweb

Корень репозитория должен содержать package.json, src, public и .github.
Workflow запускается при push в main и вручную. Загружается только dist/.

## GitHub

1. Откройте репозиторий, Settings → Secrets and variables → Actions.
2. Во вкладке Secrets создайте Repository secrets:
   - FTP_SERVER: vh470.timeweb.ru
   - FTP_USERNAME: ca432610_login
   - FTP_PASSWORD: настоящий FTP-пароль из Timeweb. Не добавляйте его в файлы или сообщения.
3. Во вкладке Variables создайте FTP_SERVER_DIR с точным путём каталога этого сайта относительно FTP-аккаунта, обязательно с / в конце. Не используйте корень FTP. Путь необходимо проверить в панели Timeweb.
4. До первой публикации сохраните резервную копию текущего содержимого каталога сайта. Одноимённые файлы будут заменяться, ранее опубликованные этим workflow устаревшие файлы могут удаляться.
5. Откройте Actions → Deploy to Timeweb → Run workflow → main → Run workflow.
6. Проверьте результат шага Upload dist to Timeweb и откройте свой домен.

Используется FTP с TLS (FTPS), с проверкой сертификата. При ошибке подключения проверьте поддержку FTPS, имя сервера и сертификат у Timeweb. Не отключайте проверку сертификата и не переходите на незашифрованный FTP автоматически.

## Локальная отправка

Если GitHub сообщает Repository not found, проверьте URL через кнопку Code в репозитории и права доступа. Для повторной авторизации используйте gh auth login --hostname github.com --web, затем gh auth setup-git.

После проверки remote и авторизации:

```sh
git add .
git commit -m "Add Astro website and Timeweb deployment"
git push -u origin main
```

Не используйте force push. Если в удалённом репозитории уже есть файлы, сначала получите и согласуйте его историю.
